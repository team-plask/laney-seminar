# 고객 대면 문체

고객이 읽는 메시지와 랜딩 카피에 적용합니다. 모든 글에 공통인 문장 원칙은
[`writing-principles.md`](writing-principles.md)에 있습니다. 이 파일은 고객에게 말하는
방식과 공개하면 안 되는 정보만 다룹니다.

## 적용 범위를 먼저 확인하기

다음 글에는 이 문서를 적용합니다.

- 고객 회신과 회신 초안
- 메신저와 이메일
- 고객 시트에 적는 설명
- 랜딩 페이지의 이름, 제목, 설명, 버튼 문구
- 자동 응답 문안

제품 사용 설명서는 `skills/laney-writing/references/guide-authoring.md`를 따릅니다. RFC, ADR, 런북과 코드 주석에는
고객 문체를 적용하지 않습니다. 해당 글도 공통 문장 원칙은 따르지만, 기술 식별자와 근거를
숨기지 않습니다.

## 존댓말로 직접 말하기

한국어는 존댓말을 사용합니다. 고객이 해야 할 행동은 `하세요`로 안내하고, Laney가 할
일은 `하겠습니다`로 약속합니다. 같은 문단에서 높임말 등급을 바꾸지 않습니다.

| 고칠 것 | 고친 것 |
|---|---|
| `확인 필요. 설정 변경 가능.` | `설정을 확인한 후에 변경할 수 있습니다.` |
| `처리가 진행될 예정입니다.` | `내일까지 처리하겠습니다.` |
| `이용에 불편을 드려 정말 죄송하고 다시 한번 사과드립니다.` | `이용에 불편을 드려 죄송합니다.` |

영어는 한국어를 직역하지 않습니다. 처음부터 영어로 작성한 뒤 의미와 약속한 범위가 같은지
확인합니다.

## 구체적인 행동과 시점을 쓰기

`빠르게`, `조만간`, `가능한 한 빨리`처럼 확인할 수 없는 표현을 쓰지 않습니다. 완료 날짜를
모르면 다음 안내 날짜를 적습니다. 원인을 아직 확인하지 못했다면 추측하지 않습니다.

| 고칠 것 | 고친 것 |
|---|---|
| `빠른 시일 내에 처리하겠습니다.` | `8월 7일까지 처리 결과를 알려드리겠습니다.` |
| `아마 권한 문제인 것 같습니다.` | `권한 설정을 확인하고 있습니다. 확인 결과는 내일 알려드리겠습니다.` |

## 내부 정보를 걸러내기

고객 글에는 다음 정보를 넣지 않습니다.

- 내부 이슈 번호
- 데이터베이스 테이블명과 컬럼명
- 저장소 경로와 UUID
- 내부 도구, 자동화 방식, 담당자 배정 내용
- 고객에게 의미가 없는 외부 업체 이름

내부 근거를 숨기라는 뜻은 아닙니다. 고객에게 필요한 결과와 다음 행동으로 바꿔 씁니다.
`customer_requests를 확인했습니다` 대신 `접수 기록을 확인했습니다`라고 씁니다.

## 날짜와 금액을 완전하게 쓰기

고객에게는 날짜를 `8월 7일`처럼 씁니다. 연도가 없으면 혼동될 때에는 `2026년 8월 7일`로
씁니다. 금액에는 천 단위 쉼표와 통화를 넣고 부가세 포함 여부를 밝힙니다.

## 고객이 통제할 수 없는 표현을 피하기

`간단히`, `쉽게`, `당연히`, `몇 번만`처럼 작업 난이도를 대신 판단하지 않습니다. 고객의
실수로 단정하지 않습니다. 문제가 발생한 사실, 확인한 범위, 다음 행동을 순서대로 씁니다.

## 보내기 전에 확인하기

- [ ] 고객에게 필요한 결론이 첫 문단에 있습니다.
- [ ] 확인하지 않은 원인이나 완료 시점을 단정하지 않았습니다.
- [ ] 내부 식별자와 구현 세부사항이 없습니다.
- [ ] 날짜와 금액을 고객이 오해하지 않게 썼습니다.
- [ ] 고객이 해야 할 다음 행동이 명확합니다.
- [ ] [`writing-principles.md`](writing-principles.md)의 공통 점검을 통과했습니다.
