# 세미나 데모 데이터

챗봇까지 만든 원장님이 **대시보드의 통계·CRM 화면을 체험**할 수 있도록
그럴듯한 더미 데이터를 넣는다. 넣은 뒤에는 대시보드에서 이렇게 물어보게 안내한다:

- "이번 달 예약 통계 내줘"
- "노쇼가 몇 건이야?"
- "채널별로 문의가 몇 건씩 왔어?"
- "일본어 문의는 누가 보냈어?"

## 데이터셋 규격 (항상 이 구성)

| 종류 | 수량 | 분산 |
|---|---|---|
| 고객 | 16명 | 한국어 7 · 영어 3 · 일본어 3 · 중국어 3, 상태 lead/qualified/active 혼합 |
| 예약 | 30건 | 지난 4주~다음 주, completed/confirmed/pending/cancelled/no_show 전부 포함, notes에 **이 병원의 실제 시술명** |
| 채널 계정 | 4종 | 카카오톡·LINE·인스타그램·WhatsApp (disconnected — 표시용) |
| 대화 | 8건 | 채널별 분산, 각 언어로 자연스러운 문의 |
| 메시지 | 대화당 2~3개 | user 질문 + assistant 답변 (가격 숫자는 지어내지 않음 — "확인 후 안내" 톤) |

**식별 규칙**: 모든 더미 고객의 이메일은 `{이름}@demo.laney.app`.
이것이 삭제 필터다. 실제 고객과 절대 섞이지 않는다.

## 진행 순서

1. 시술명 확보: `products__list`에서 실제 상품명 몇 개를 뽑아 예약 notes에 쓴다.
2. `accounts__insert`로 채널 계정 4종 (status: disconnected).
3. `customers__insert` ×16 — 위 규격, 이메일 규칙 준수.
4. `reservations__insert` / `conversations__insert` / `messages__insert` 시도.

⚠️ **LNY-1527 게이트**: 현재 MCP 경계가 예약의 `customer_id`, 대화의
`account_id`/`customer_id`, 메시지의 `conversation_id`를 벗겨낸다 (실측).
**한 번만 시도**하고 참조가 붙지 않으면: 고객·채널 계정까지만 남기고,
"예약·대화 데모는 담당자가 준비해 드립니다"라고 안내한 뒤 멈추지 말고 진행한다.
수정 배포 후에는 이 스킬 그대로 전량 동작한다.

## 대화 내용 규칙

- 각 언어로 자연스럽게: 예약 문의, 예약 변경, 가격 문의, 영업시간 문의.
- **assistant 답변에 가격 숫자를 지어 넣지 않는다** — "정확한 금액은 확인 후
  안내드리겠습니다" 톤 유지. 더미여도 never-wrong 철학과 어긋나는 예시를 남기지 않는다.
- 병원 전화번호는 코퍼스의 실제 번호를 쓴다.

## 정리 (데모 후)

원장님이 "더미 데이터 지워줘"라고 하면:
`@demo.laney.app` 이메일의 고객을 찾아 그 고객들의 예약·대화·메시지 → 고객 →
disconnected 채널 계정 순으로 삭제한다. 실제 데이터는 이메일 필터 밖이므로 안전하다.
