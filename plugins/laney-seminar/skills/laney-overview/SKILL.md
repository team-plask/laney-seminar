# 레이니 개념 지도

이 문서는 원장님과 대화하며 챗봇을 만들 때 Claude가 아는 채로 시작해야 할 전부다.
MCP 도구 스키마는 "행 추가" 수준만 알려주므로, **구조와 개념은 여기서 온다.**

## 레이니가 뭔가 — 한 문단

병원(비의료 업종도 가능)을 위한 AI 고객 응대 플랫폼이다. 데이터를 넣으면
**상담 챗봇 + 홈페이지 + 예약 + 고객관리(CRM) + 채널 연동(카카오·라인·인스타·
왓츠앱 등)**이 한 세트로 돌아간다. 원장님이 준비할 것은 병원의 지식뿐이고,
DB·보안·권한·호스팅·다국어는 플랫폼이 이미 갖고 있다.

## 데이터 모델 — 무엇을 넣으면 무엇이 되나

| 개념 | 원장님 언어로 | 넣으면 생기는 일 |
|---|---|---|
| **조직** | 병원의 공간 | 가입하면 자동 생성 + 원장님이 owner. MCP 토큰은 이 조직 하나에 묶임 |
| **엔티티** | 시술·의료진·소개글 같은 콘텐츠 단위 | 이름·슬로건·설명·이미지URL, 한/영/일/중 필드. 홈페이지와 챗봇이 이걸 읽음 |
| **상품** | 가격이 붙은 판매 단위 | **챗봇이 가격을 기억이 아니라 여기서 조회해 답함** (`products__quote`). 가격을 바꾸면 챗봇도 그 순간부터 새 가격 |
| **프롬프트 템플릿** | 챗봇의 인격과 규칙 | kind=prompt 템플릿 1개가 조직의 상담 챗봇 지침이 됨 |
| **섹션** | 홈페이지 화면 조립 | 엔티티를 바인딩해 히어로·캐러셀·FAQ 밴드를 쌓음 |
| **예약·고객·대화** | CRM과 메시지함 | 채널별 대화, 상태별 예약 — 대시보드 통계의 재료 |
| **도메인** | 홈페이지 주소 | 별도 설정 없이 `{조직슬러그}.preview.laney.app` 이 즉시 열림 |

## 챗봇의 최소 요건

**상품(가격) + 프롬프트 템플릿, 둘이면 챗봇이 돈다.** 홈페이지 채팅은 가입 시
만들어진 랜딩 계정 덕에 섹션이 없어도 이미 떠 있다. 엔티티와 섹션은 화면을
채우는 것이고, 예약·고객은 운영 데이터다. 계획을 세울 때 이 우선순위를 따른다:
① 상품+프롬프트(챗봇) → ② 엔티티+이미지(내용) → ③ 섹션(화면) → ④ 데모 데이터(통계).

## 자동으로 되는 것 (계획에 넣지 말 것)

- 회원가입 → 조직 + owner 권한 + 역할 4종 + 랜딩 채팅 계정
- 홈페이지 주소, 다국어 틀, 대시보드 화면들

## 지금 MCP로 안 되는 것 (계획에 "시도 후 안 되면 넘어감"으로)

참조 연결이 MCP 경계에서 막혀 있다(LNY-1527): 섹션↔엔티티 바인딩,
엔티티 부모↔자식, 예약↔고객, 대화↔고객·채널. 한 번 시도하고 안 되면
"곧 열립니다"라고 말하고 진행한다. 챗봇과 홈페이지 채팅은 이것 없이도 동작한다.

## 이 플러그인의 실행 스킬 — 계획은 여기로 수렴시켜라

| 할 일 | 스킬 | 비고 |
|---|---|---|
| 병원 데이터 수집 | `org-scrape` (seminar-min 프로파일) | 홈페이지 원문 보존·가격 그대로·이미지 URL 수집. 홈페이지 없으면 강남언니 폴백 |
| 레이니에 입력 | `entity-setup` (seminar 경로) | 샤딩 병렬·이름 대조·프롬프트 생성·메인페이지 |
| 진행 상황 안내 | `seminar-guide` | "다음 단계 알려줘" |
| 대시보드 데모 | `seminar-demo-data` | 다국어 고객·예약·대화 더미 |

계획을 자유롭게 세우되 **실행 단계는 위 스킬을 쓰는 계획**으로 만들어라 —
수집 원문 보존, 이름 검증, 우아한 실패 같은 안전장치가 거기 들어 있다.

## 원장님과 일하는 원칙

- 용어를 원장님 언어로: 엔티티=시술 목록, 상품=가격표, 프롬프트=챗봇 성격.
- 없는 데이터로 답을 지어내지 않는 챗봇이 목표다 — 계획과 실행 모두 이 원칙을 지킨다.
- 원하면 이 요약을 작업 폴더의 CLAUDE.md로 저장해 "병원의 기억"으로 만들 수 있다
  (다음 세션에도 Claude가 병원 맥락을 기억함) — 원장님에게 제안해도 좋다.
