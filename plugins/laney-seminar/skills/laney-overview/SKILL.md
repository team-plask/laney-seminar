# 레이니 개념 지도

MCP 도구 스키마는 "행 추가" 수준만 알려준다. **구조와 개념은 이 스킬이 공급한다.**
개별 필드·메커니즘이 필요해지면 [references/platform-model.md](references/platform-model.md)를 읽어라.

## 레이니가 뭔가 — 한 문단

병원을 비롯한 사업장을 위한 AI 고객 응대 플랫폼. 데이터를 넣으면 **상담 챗봇 +
홈페이지 + 예약 + 고객관리 + 채널 연동**(카카오·라인·인스타·왓츠앱·위챗·전화 등
16종 플랫폼)이 한 세트로 돌아간다. DB·보안·권한·호스팅·4개 국어 틀은 플랫폼에
이미 있고, 사업장이 채울 것은 자기 지식뿐이다.

## 여섯 개의 기둥 — 무엇을 넣으면 무엇이 되나

| 개념 | 원장님 언어 | 핵심 한 줄 |
|---|---|---|
| 조직 | 병원의 공간 | 가입 시 자동 생성, 원장님=owner(`['*']`). 모든 데이터가 여기 격리 |
| 엔티티(+연결) | 시술·의료진·소개 콘텐츠 | 유일한 콘텐츠 원시형. 4개 국어 필드, 부모-자식 **그래프**로 재사용 |
| 상품(+프로모션) | 가격표와 이벤트 | 챗봇이 가격을 **조회로** 답함(`products__quote`). 프로모션은 날짜 규칙으로 자동 적용 |
| 프롬프트 템플릿 | 챗봇의 성격과 규칙 | 조직 기본 프롬프트 + 채널별 오버레이가 병합됨 |
| 섹션 | 홈페이지 조립 | 엔티티(와 그 자식들)를 바인딩해 화면을 쌓음 |
| 예약·고객·대화 | 운영 데이터 | 채널 불문 한 고객으로 통합, 영업시간·정원 규칙으로 예약 판정 |

## 챗봇 최소 요건과 계획 우선순위

**상품 + 프롬프트 템플릿이면 챗봇이 돈다.** 홈페이지 채팅은 가입 시 만들어진
랜딩 계정 덕에 섹션 없이도 이미 떠 있다. 계획은 이 순서로:
① 상품+프롬프트(챗봇) → ② 엔티티+이미지(내용) → ③ 섹션(화면) → ④ 데모 데이터(통계).

**첫인사와 추천 칩은 프롬프트가 아니라 조직 설정(`assistant_intro`)이다.**
말투는 프롬프트 템플릿, 첫마디는 `organizations__update`로 — 헷갈리기 쉬운 지점.

## 자동으로 되는 것 (계획에 넣지 말 것)

가입 → 조직 + owner + 역할 4종(owner/admin/member/customer) + 랜딩 채팅 계정.
홈페이지 주소는 `{slug}.preview.laney.app`로 즉시. 다국어 틀·대시보드 화면 기본 제공.

## 지금 MCP로 안 되는 것 (계획에 "시도 후 안 되면 넘어감"으로)

참조 연결이 MCP 경계에서 벗겨진다(LNY-1527): 섹션↔엔티티, 엔티티 부모↔자식,
예약↔고객, 대화↔고객·채널, 상품↔엔티티. 한 번 시도하고 안 되면 말하고 진행한다.
챗봇과 홈페이지 채팅은 이것 없이도 동작한다.

## 실행은 이 스킬들로 수렴시켜라

수집 `org-scrape`(seminar-min, 홈페이지 없으면 강남언니 폴백) → 입력
`entity-setup`(seminar 경로: 샤딩·이름 대조·프롬프트·메인페이지) → 진행 안내
`seminar-guide` → 대시보드 데모 `seminar-demo-data`. 계획은 자유롭게 세우되
실행 단계는 이 스킬을 쓰는 계획으로 — 원문 보존·검증·우아한 실패가 거기 들어 있다.

## 원장님과 일하는 원칙

용어는 원장님 언어로(엔티티=시술 목록, 상품=가격표, 프롬프트=챗봇 성격).
없는 데이터로 답을 지어내지 않는 챗봇이 목표다. 원하면 이 요약을 작업 폴더
CLAUDE.md로 저장해 "병원의 기억"으로 만들 것을 제안해도 좋다.
