# 예약 규칙 설정

챗봇이 가격을 답하는 데까지 왔으면 그다음은 예약이다. 순서가 중요하다.
**받을 정보를 먼저 정하고, 그 정보 위에 규칙을 세운다.** 규칙 중 하나(동시 예약
수)는 "무엇을 기준으로 셀 것인가"를 커스텀 필드에서 가져오기 때문이다.

## 시작 전에 알아야 할 것 (실측 2026-08-30)

- **규칙이 하나도 없으면 예약 가능 시간이 0개다.** `reservations__availability`가
  빈 배열을 돌려주고, 챗봇은 어떤 시간도 제안하지 못한다. 즉 이 단계를 건너뛰면
  예약 기능은 존재하지만 아무 시간도 안내되지 않는다.
- **규칙 4종의 강제 지점이 다르다.** `capacity`만 데이터베이스가 직접 막는다
  (트리거 `enforce_reservation_capacity`, 위반 시 `availability_capacity_exceeded`).
  `hours`·`block`·`gap`은 **제안되는 시간을 깎는** 규칙이라, 챗봇은 그 시간을
  제안하지 않지만 대시보드에서 손으로 넣는 예약까지 막지는 않는다.
  원장님께 설명할 때: "겹치는 예약은 시스템이 막고, 영업시간과 휴진일은 챗봇이
  애초에 제안하지 않습니다."

## 1단계 — 예약 때 무엇을 받을지 (커스텀 필드)

먼저 여쭙는다. 한꺼번에 나열하지 말고 **기본 3개를 제안하고 확인받는 방식**으로.

> "예약을 받으려면 손님한테 뭘 물어봐야 할지부터 정해야 합니다. 보통은 성함,
> 연락처, 희망 시술 세 가지인데 이대로 갈까요? 더 받고 싶은 게 있으실까요?
> 첫 방문인지, 어떻게 알고 오셨는지 같은 걸 받는 병원도 있습니다."

`custom_fields__insert`로 넣는다. `target: "reservations"`가 필수다.

| 필드 | key | kind | 비고 |
|---|---|---|---|
| 성함 | `booker_name` | `text` | required |
| 연락처 | `phone` | `phone` | required |
| 희망 시술 | `treatment` | `select` | required, `options`에 시술명을 쉼표로 |
| 첫 방문 여부 | `first_visit` | `select` | `첫방문,재방문` |
| 내원 경로 | `visit_source` | `select` | `인스타그램,지인 추천,네이버,강남언니,기타` |
| 요청 사항 | `note` | `textarea` | |

- `kind`는 `text · phone · email · select · multi-select · textarea · number ·
  date · switch · url · file · entity · member` 중에서 고른다.
- `select`의 `options`는 **쉼표로 이어 붙인 한 줄 문자열**이다(배열이 아니다).
  희망 시술의 보기는 **이미 넣은 상품 이름에서 가져온다** — 손님이 고른 값이 곧
  규칙의 기준값이 되므로, 상품명과 철자가 다르면 규칙이 어긋난다.
- `visibility: "public"`이 손님에게 보이는 필드, `private`은 내부 기록용이다.
- 받은 값은 예약의 `custom`에 `{"treatment":"울쎄라", ...}` 형태로 저장된다.

**개인정보는 필요한 것만.** 주민번호·상세 병력은 받지 않는다. 원장님이 요청해도
"예약 단계에서는 연락 가능한 정보까지만 받고, 나머지는 내원 시 받으시는 게
안전합니다"라고 말한다.

## 2단계 — 예약 규칙 (availability_rules)

필드가 정해졌으면 규칙을 여쭙는다. 넷을 순서대로, 하나씩.

**① 영업시간과 예약 간격** — "평일 몇 시부터 몇 시까지 예약을 받으실까요?
그리고 예약은 몇 분 단위로 끊을까요? 보통 30분입니다."

```
kind: "hours", weekdays: "mon,tue,wed,thu,fri",
start_time: "10:00", end_time: "20:00", slot_minutes: 30
```

- `weekdays`는 `mon,tue,wed,thu,fri,sat,sun` 중 쉼표로 이어 붙인 한 줄.
  **비워 두면 매일**이다.
- 토요일 시간이 다르면 **행을 하나 더** 만든다(`weekdays: "sat"`). 요일마다
  다른 시간은 규칙을 나누는 것으로 표현한다.
- `slot_minutes`는 5~240.

**② 동시에 몇 명** — "같은 시간에 시술을 몇 분까지 받으실 수 있나요? 기준은
시술별로 볼까요, 병원 전체로 볼까요?"

```
kind: "capacity", scope_key: "treatment", max_concurrent: 1, slot_minutes: 30
```

- `scope_key`에 **1단계에서 만든 필드의 key**를 넣는다. `treatment`를 넣으면
  "같은 시술은 같은 시간에 1명"이 되고, 비워 두면 병원 전체 기준이 된다.
- 장비가 병목이면 `equipment` 같은 필드를 따로 만들어 그 key를 쓴다.
- **이 규칙만 데이터베이스가 직접 막는다.** 실측: 같은 시술·같은 시간 두 번째
  예약이 `availability_capacity_exceeded`로 거부됐다.

**③ 예약 사이 간격** — "시술 사이에 정리 시간이 필요하신가요?"

```
kind: "gap", scope_key: "treatment", gap_minutes: 20
```

같은 기준값의 예약 사이에 최소 N분을 띄운다(5~240). 고정 격자가 아니라 실제
예약 시각 기준으로 앞뒤를 본다.

**④ 휴진일** — "쉬는 날이 있으면 지금 넣어두죠. 추석이나 정기 휴진일 같은 거요."

```
kind: "block", starts_at: "2026-09-24T00:00:00+09", ends_at: "2026-09-27T00:00:00+09"
```

정기 휴일(매주 일요일)은 block이 아니라 **①의 weekdays에서 빼는 것**으로 표현한다.

## 3단계 — 넣고 나서 바로 확인

`availability_rules__list`로 넣은 규칙을 다시 읽어 원장님께 **말로** 정리한다.
"평일 10시부터 8시까지 30분 단위, 토요일은 5시까지, 같은 시술은 같은 시간에
한 분, 추석 사흘은 휴진으로 넣었습니다."

그다음 `reservations__availability`를 실제로 호출한다.

```
date: "2026-09-02", custom: { "treatment": "울쎄라" }
```

- 슬롯이 나오면 성공이다. 몇 개가 나왔는지 숫자로 말한다.
- **빈 배열이면** 규칙이 안 들어갔거나 그날이 휴무다. 넘어가지 말고 원인을 찾는다.
- `custom`을 함께 넘겨야 정확하다. 규칙이 무엇을 예약하는지에 따라 달라지기 때문.

## 4단계 — 원장님이 직접 돌려보는 테스트

규칙이 들어갔으면 **챗봇에게 직접 물어보게 한다.** 네 개를 순서대로 건넨다.
각각 무엇을 확인하는 테스트인지 한 줄로 알려준다.

1. `이번 주 수요일에 울쎄라 예약 가능한 시간 알려줘`
   → 영업시간 규칙대로 시간이 나오는지. 10시 이전이나 8시 이후가 섞여 있으면 잘못된 것.
2. `일요일에 예약할 수 있어?` (또는 휴진 요일)
   → 쉬는 날을 제안하지 않는지. "그날은 어렵다"고 답해야 정상.
3. `추석 연휴에 예약돼?`
   → 휴진 기간 규칙이 먹는지.
4. `수요일 2시에 울쎄라로 예약해줘` → 그다음 **같은 시간에 한 번 더**
   → 두 번째는 막히거나 다른 시간을 제안해야 정상. 실측된 동시 예약 방지.

테스트 중에 챗봇이 예약을 잡으면 대시보드(https://dashboard.laney.app)의
Reservations에서 실제로 들어왔는지 함께 확인한다. 연습으로 넣은 예약은
`방금 테스트로 넣은 예약 지워줘`로 정리한다.

## 자주 나오는 상황

| 증상 | 원인과 대응 |
|---|---|
| 예약 가능 시간이 하나도 안 나온다 | 규칙 0개이거나 그날이 weekdays에 없다. `availability_rules__list`로 확인 |
| 영업시간 밖 시간이 제안된다 | `hours` 규칙이 여러 개라 겹친다. 요일이 중복되지 않게 정리 |
| 같은 시간에 두 건이 들어갔다 | `capacity` 규칙이 없거나 `scope_key`가 실제 필드 key와 다르다 |
| 시술을 골라도 시간이 안 바뀐다 | `scope_key`와 커스텀 필드 key의 철자를 대조 |
| 손님이 시술 이름을 다르게 말한다 | `select` options를 상품 이름과 일치시킨다 |

## 하지 않는 것

- 원장님이 말하지 않은 시간·정원을 임의로 넣지 않는다. 모르면 여쭙는다.
- 기존 규칙을 덮어쓰기 전에 무엇이 있는지 먼저 읽고 알린다.
- 예약 확정 문구를 지어내지 않는다. 예약 도구가 성공을 돌려주기 전에는
  "예약됐습니다"라고 말하지 않는 게 챗봇 프롬프트의 원칙이다.
